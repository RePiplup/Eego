## 结论

前轮两项主要意见在当前源码中均已落实，未发现这次修订引入的新增阻断问题。

1. 已有 library-continuity.json 不再仅凭备份目录存在就通过。现在要求库路径匹配、备份规范路径位于 home/rollback 下、清单包含 tasks.record，并逐文件验证存在、普通文件、非符号链接、可读、完整读取及 SHA-256 一致。清单文件名拒绝斜杠、反斜杠和父目录项。损坏或缺失会拒绝继续，保留原库。
2. Qt native host 在找到现存窗口时校验其进程 EXE 必须为当前包 HandmadeBTQuick.exe；handoff 在最终发送前再次校验；状态查询同样校验。旧 GUI 使用同一任务库时不会再仅凭窗口类匹配被新桥接接受。
3. 临时探锁保存 Windows 错误码，便于区分占用和其他无法打开情形。库路径解析由 Qt 与 Qt native host 共用，链接不存在时才使用自身 userdata，链接非法时不静默另建空库。
4. 静态检查仍显示备份在持有独占 ui.lock 时进行，生成备份与回执均使用 QSaveFile；完成备份后才释放锁并启动核心。核心仍需自行获取同一库的排他锁。释放到核心获取之间的竞争由核心失败关闭，而不是靠临时锁永久跨进程传递。
